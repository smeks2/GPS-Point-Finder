# v3.4.4b Multi Pin Save & List Fix

Fixed root cause: PointStore.add() tried to write Float.NaN into JSONObject for manually added coordinates. org.json rejects non-finite numeric values, and the catch block silently discarded the save. Accuracy for manual points is now JSON null. Saving now returns a boolean and displays a success/failure message. Empty SENARAI now shows a list-specific empty state instead of immediately opening the Add dialog. Existing saved points are retained via the same points_v3 preferences key.
